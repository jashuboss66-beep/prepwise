# Prepwise: AI-Powered Adaptive Placement Preparation System

A local Windows prototype built with React, Vite, Tailwind CSS, Flask, SQLAlchemy, SQLite, NVIDIA Nemotron through OpenRouter, and Chart.js. Phases 1-6 are implemented. Phase 7 covers final integration, testing, and packaging.

## Project structure

```text
backend/
  app/
    routes/       Authentication, assessments, AI, adaptive practice, rewards, readiness
    services/     Nemotron, adaptive learning, gamification, readiness calculations
    models.py     SQLAlchemy models
    question_bank.py
  tests/          Backend workflow and integration tests
  instance/       Local SQLite database (created automatically)
  .env.example    Safe configuration template; contains no API key
  requirements.txt
  run.py
frontend/
  src/            React pages and components
  scripts/dev.js  Starts Flask and Vite together
  package.json
  package-lock.json
start.bat          Windows setup and start helper
README.md
PROGRESS.md
```

## Requirements

- Windows 10 or newer
- Python 3.10 or newer, with the Python Launcher (`py`)
- Node.js 20.19+ or 22.12+ (npm is included)
- Internet access for first-time Python and Node package installation; an API key is optional

## Quick start on another Windows laptop

1. Copy or extract the project folder. Do not copy `node_modules`, `.venv`, `__pycache__`, `frontend/dist`, `backend/.env`, or the local SQLite database unless you intentionally need that student's data.
2. Optional AI setup: copy `backend/.env.example` to `backend/.env`, then follow [NVIDIA Nemotron API setup](#nvidia-nemotron-api-setup). Without a key, the application still runs with local AI fallbacks.
3. Double-click `start.bat`. It creates `backend/.venv`, installs backend requirements and frontend packages when missing, then starts Flask and Vite.
4. Open the URL printed by Vite, normally <http://localhost:5173>. Keep the start window open while using the app. Close it to stop the local servers.
5. Register with a name, email, and password. SQLite tables and the question bank initialize automatically at first startup.

### Manual setup

From the project root in PowerShell:

```powershell
py -3 -m venv backend\.venv
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
cd frontend
npm ci
$env:PYTHON = (Resolve-Path "..\backend\.venv\Scripts\python.exe").Path
npm run dev
```

Open the Vite URL shown in the terminal. The `dev` launcher starts a fresh Flask process on the first available port from 5000–5099; Vite proxies `/api` calls to that exact process. This avoids silently reusing an older Flask instance with stale settings. For frontend-only development where Flask is started separately, use `npm run dev:web`.

## NVIDIA Nemotron API setup

The integration uses OpenRouter's Chat Completions API and the free model `nvidia/nemotron-3-ultra-550b-a55b:free`.

1. Create an OpenRouter API key in your own account.
2. Copy `backend/.env.example` to `backend/.env`.
3. Set `OPENROUTER_API_KEY` to your key. You may also replace `FLASK_SECRET_KEY` with a private random value.
4. Restart the application.

The key is read by Flask only and is not included in frontend source or API responses. Keep `backend/.env` private; it is ignored by Git. Never paste a real key into `README.md`, source files, or `frontend/.env`. If the key is blank, rate-limited, or the model returns invalid content, local fallback analysis, tutor replies, and questions remain available.

## Database and student data

Flask creates `backend/instance/placement_prep.sqlite3`, tables, question metadata, and seeded questions on application startup. No separate migration command is needed for a fresh local install. Student accounts, assessment and practice history, AI history, rewards, company preferences, and saved placement reports persist in this SQLite file.

The database is intentionally excluded from source control and should not be sent with a clean source package. To move existing student records, stop the application and separately copy the SQLite file securely; keep the same `FLASK_SECRET_KEY` if preserving existing login sessions matters. Assessment answers are graded by Flask. Performance, readiness, and rewards are calculated from saved records, not generated by the model.

## Implemented workflows

- Account registration, login, logout, and protected pages.
- Timed 20-question initial assessment across aptitude, logical reasoning, verbal ability, and technical skills, with saved answers and detailed results.
- Nemotron skill analysis, tutor chat, and validated practice MCQs, with local fallbacks.
- Adaptive subject/topic practice with difficulty selection, explanations, topic mastery, and per-student repetition tracking.
- Backend-awarded XP, coins, levels, achievements, streaks, and an XP leaderboard.
- Placement readiness, skill gaps, target-company preparation guidance, a saved report, and five Chart.js analytics.

## Additional batch 1: personalized learning management

- The **My plan** page lets students save college, degree, department, graduation year, CGPA, technical skills, programming languages, preferred language, target companies, target roles, and daily/weekly study targets. Account name and email remain in the existing account record; target companies reuse the existing company-preference table.
- Daily plans use saved adaptive topic recommendations, assessment baselines, and pending tasks from earlier days. The Python backend selects topics and difficulty deterministically; students can mark plan tasks complete.
- Daily and weekly missions aggregate saved answered questions, completed practice sessions, topic accuracy, and study-goal progress. Completion rewards are written once to the existing reward ledger, so reloading a mission cannot pay it twice.
- Daily and weekly study goals compare saved activity with the student’s configured target. Study minutes are estimates: two minutes per answered practice question (capped at 60 per session), and elapsed assessment time with an answer-based fallback when elapsed time is unavailable. Planner task checkmarks are kept separate from measured performance.
- The in-app notification center records daily plans, missed daily goals, mission completion, achievements, level upgrades, and streak milestones. Notifications and learning records are scoped to the logged-in student.
- Main endpoints are `/api/learning/profile`, `/api/learning/plan`, `/api/learning/missions`, `/api/learning/goals`, and `/api/learning/notifications`.

## Readiness interpretation and known limits

Readiness uses `R = (0.25A + 0.25T + 0.25C + 0.15M + 0.10S) / sum(available component weights)`. Missing components are marked Pending and omitted from the denominator, so they are not treated as zero. Aptitude and Technical use actual answered assessment and practice items. The current timed placement assessment is a disclosed proxy for Mock assessment performance. There is no coding-task evaluator in this prototype, so Coding remains Pending until such records exist. Consistency is based on meaningful learning days during the trailing 30 days, at 5 points per day up to 100.

The readiness score is a preparation progress indicator, not a probability of getting a job. Target-company guidance is general and does not assert current company hiring requirements or guarantee eligibility. The current account profile stores name and email; target company preferences are optional and saved separately. The free model may be unavailable or rate-limited, in which case labeled local fallbacks are used.

## Troubleshooting

- **`py` is not recognized:** install Python and select the option to install the Python Launcher, or use the manual setup with your Python executable.
- **`node` or `npm` is not recognized:** install Node.js 20.19+ and reopen the terminal.
- **First start cannot install packages:** check internet access, then run `start.bat` again. Dependencies are pinned by `requirements.txt` and `package-lock.json`.
- **Another local server is already running:** `start.bat` chooses a free API port from 5000–5099 and routes requests to its newly started Flask process. Keep the launcher window open and open the exact Vite URL printed there.
- **Port 5173 is busy:** Vite prints another available port (such as 5174); open that exact URL. The launcher routes API requests to the fresh Flask process it started.
- **AI screens show fallback content:** verify `backend/.env`, the `OPENROUTER_API_KEY` value, and network access. The rest of the prototype works without AI connectivity.
- **Coding practice shows an HTTP 403:** the public compiler service or the current network rejected the request. Restart with start.bat after updating, then read the response detail in the banner or launcher terminal. This is a runner access issue, not a compile error in the student's code.
- **A student's history appears missing:** confirm the app is using the intended `backend/instance/placement_prep.sqlite3` file. A clean source transfer does not include existing database records.
- **Need to reset local demo data:** stop the servers and remove the local SQLite file; the database and question bank are recreated on the next startup. This permanently deletes local accounts and history.

See [PROGRESS.md](PROGRESS.md) for implementation status.

## Placement Learning Hub

Open **Learning Hub** in the app navigation (or `/placement-hub`) for three connected modes:

- **Normal practice** is untimed. Choose Aptitude, Communication, or Technical, then pick a topic, difficulty, and set size. Answers are checked by Flask and show immediate feedback; bookmarks, answer history, topic mastery, and rewards use the existing practice and reward records.
- **AI assessment** creates a timed assessment from the existing question bank. It randomizes questions and option order, saves answers, submits when the timer expires, and uses the existing Nemotron/OpenRouter analysis service when available. Scores and chart metrics are calculated from saved answers in Python; local fallback feedback remains available offline.
- **Daily quiz** saves a 10-question set (four Aptitude, three Communication, and three Technical) per student and quiz date. Its deadline is configurable with `DAILY_QUIZ_CUTOFF_UTC_HOUR` (UTC hour, 0–23; default `23`). Existing daily/weekly missions and the reward ledger handle completion and duplicate prevention.

The bank has 600 Hub questions: 200 Aptitude, 150 Communication, and 250 Technical. The complete topic and difficulty counts, source/licence metadata, and validation limits are in [QUESTION_BANK_REPORT.md](QUESTION_BANK_REPORT.md). The original Logical Reasoning questions remain part of the earlier assessment system and are outside these Hub totals.

Useful endpoints are under `/api/hub`: `/taxonomy`, `/overview`, `/normal/sessions`, `/normal/history`, `/bookmarks`, `/assessments`, and `/daily-quiz`. All routes require the existing authenticated session and scope records to the signed-in student.


## Interface design

The student workspace uses a responsive collapsible navigation sidebar, a compact page header with notifications and profile actions, and a consistent ivory, charcoal, forest-green, sage, and amber visual palette. The layouts adapt to mobile screens and honor reduced-motion preferences. Profile editing and notifications remain in the Learning Planner, company targets remain in Placement Readiness, and daily challenges remain in Learning Hub. Dashboard metrics and charts are loaded from saved student records; empty states are shown when a student has no activity yet.


### Daily focus and accessible analytics

The dashboard's Today card combines the first saved plan task, the daily study goal, and completed mission count, then links to the right next step for new and returning students. After adaptive practice, the result view summarizes actual topic answers and offers a focused retry for the weakest topic in that session. Readiness charts provide adjacent text summaries for screen readers and chart users who prefer a text description.

## Demo coding practice

Open **Coding Practice** (`/coding`) for three original DSA exercises covering arrays and hashing, maximum-subarray sums, and binary search. The problem themes follow topic areas in [Striver's A2Z DSA Sheet](https://takeuforward.org/dsa/strivers-a2z-sheet-learn-dsa-a-to-z); the problem statements, examples, and test cases are original demo content. The screen supports Python, C++, Java, and JavaScript starter templates, sample runs, a custom stdin input/output terminal, hidden test submission, saved per-student submission history, and a one-time reward for the first accepted solution to each problem. It runs code through Wandbox, resolves compiler versions from the live compiler catalog, and reports compile errors, wrong answers, service outages, and rate limits. No Judge0 or AI API key is needed for code execution. A student's best test pass rate for each attempted problem supplies the coding component of placement readiness.

Flask sends code to the public [Wandbox compiler service](https://wandbox.org/); the Flask process never executes student code. Wandbox provides a sandboxed compile API without requiring a Judge0 token, and the application looks up current compiler IDs instead of relying on fixed language IDs. The service is a volunteer-run public service with no availability guarantee, so coding practice requires internet access and may be unavailable during service interruptions. Code submitted for execution is sent to that service. Set `WANDBOX_API_URL` in `backend/.env` only if using a compatible Wandbox instance. This is a small demo bank, not the complete multi-language coding system described in the broader project requirements.
